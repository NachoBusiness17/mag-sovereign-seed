## 1. The Mission (One Paragraph)

This project collects and structures **self-contained build prompts** — single instructions that cause an LLM to produce a complete, playable game — for every known game across every culture and era, from Senet and Go to Mahjong, Sudoku, and solo RPG systems. The structuring principle is **cache farming**: arranging prompt content into layers so that the largest possible share of every request hits the provider's prompt cache, cutting cost by 50–90% and latency by up to 85% on long prompts 【turn0search15】【turn0search18】【turn0search19】. The five-millennium history of games makes this tractable because world games compress into a handful of shared mechanical families — the history is the cache manifest.

**Companion documents** (read after this one): the full research deep dive (`01_DEEP_DIVE.md`), the Mahjong×Sudoku integration architecture (`02_TILE_PUZZLE.md`), and the universal corpus extension (`03_UNIVERSAL_CORPUS.md`).

## 2. Core Vocabulary (Definitions Before Use)

| Term | Definition |
| :--- | :--- |
| **Cache farming** | Structuring prompts to maximize cache-hit share of tokens, per §3 Facts 1–3. |
| **Static prefix** | Prompt content identical across many requests (rules, schemas, contracts). Cacheable. |
| **Dynamic tail** | Request-specific content (game state, seed, instance). Never cached; keep it last and small. |
| **Layer L0–L4** | The corpus's five content strata, defined in §4. L0 = universal contract; L1 = family engines; L2 = game statics; L3 = variant/cultural packs; L4 = live instance state. |
| **Engine (family engine)** | A shared mechanical specification covering a whole game family (e.g., the race/dice engine covers Senet, Ur, Patolli, Pachisi, Ludo). |
| **Pack** | A small delta (~100–800 tokens) that specializes an engine into one game or variant (Riichi pack, Killer-Sudoku pack, Patolli cultural pack). |
| **Instance** | One live game state: board string, hand encoding, seed, session context. |
| **Verifier** | Deterministic code or protocol that checks legality, uniqueness, solvency, or inventory. The LLM *calls* verifiers; it never *is* one. |
| **Six-function contract** | The universal game schema: `state encoding · initial state · legality · transition · terminal detection · scoring`. Every game fills in the same six slots. |
| **Output contract** | Cached instructions forcing the model to restate state canonically and cite rules before answering. Primary anti-hallucination device. |
| **Canonical encoding** | The corpus's compact notations: Tenhou mahjong notation, 81-char Sudoku strings, FEN/PGN, SGF/kifu, `XdY+Z` dice algebra. |
| **One-shot generation** | Producing a complete playable game from a single structured prompt 【turn0search5】【turn0search11】. |
| **Research-status field** | The `attested / reconstructed / speculative` flag plus source list carried by every historical pack (§3 Fact 8). |

## 3. Ten Established Facts (the Load-Bearing Claims)

**Fact 1 — LLMs recompute their whole prompt every call, and caching stops that.** Each autoregressive step requires prefilling Key/Value (KV) attention tensors for the entire prefix; a 4K-token context can occupy ~1.3 GB of GPU memory in KV alone 【turn0search17】. Prompt caching stores those tensors keyed to the prompt 【turn0search15】.

**Fact 2 — Caching is exact-prefix.** A one-byte difference at position *N* invalidates the cache for everything after *N* 【turn0search18】【turn0search16】. *This single mechanical fact generates the entire architecture: variable content goes last, static content first, byte-identical formatting throughout.*

**Fact 3 — The economics are decisive.** Cached-read pricing runs ~0.1× base input (Anthropic, DeepSeek) to ~0.5× (OpenAI); measured savings are 50–90% of cost and up to 85% of latency on long prompts 【turn0search18】【turn0search17】【turn0search19】. Anthropic exposes explicit `cache_control` breakpoints; OpenAI is fully automatic — so corpus layout must assume exact prefixes regardless of provider 【turn0search19】.

**Fact 4 — Caches especially help long-horizon agentic work** — the exact profile of game sessions and generation pipelines — per the dedicated 2026 arXiv evaluation of prompt caching for long-horizon agentic tasks.

**Fact 5 — The LLM must never be the solver.** Generalized chess is EXPTIME-complete (Fraenkel & Lichtenstein, 1981); generalized Go likewise (Robson, 1983). Solved-game results confirm scale: checkers is a proven draw (Schaeffer et al., 2007), Awari/Oware a proven draw (Romein, 2002), Go 19×19 has ~10¹⁷⁰ legal positions (Tromp, 2016), and 16-given Sudoku provably cannot force uniqueness (McGuire et al., 2012 — 17 is the minimum). **Corollary:** the LLM emits instances and applies rules; legality, uniqueness, difficulty, and win-checks go to deterministic verifiers defined in cached protocol blocks.

**Fact 6 — State drift is a documented, empirically studied failure mode.** Field builds report LLM game masters losing track of game state, under-challenging players, and acting without player input 【turn0search2】. The studied remedy is a multi-agent split — a Narrator for fiction, an Archivist for state — which measurably improved player experience (arXiv 2502.19519 【turn0search4】). The corpus's layered design operationalizes this: the Archivist owns dynamic layers only.

**Fact 7 — World games compress into ~7 engine families** (race, war/capture, sowing, tile, card, constraint-puzzle, narrative), a taxonomy established by Murray's *A History of Board-Games Other Than Chess* (1952), extended by Parlett and Culin. Therefore "all games in all cultures" = thousands of small packs over a handful of engines, not thousands of prompts.

**Fact 8 — Ancient rules are contested, and the corpus carries that honestly.** Senet's rules exist only as competing scholarly reconstructions (Kendall, 1978; Piccione, 1990). The Royal Game of Ur's rules come from Babylonian tablet BM 33333, decoded by Irving Finkel (2007–08) — written ~2,400 years after the boards. Hnefatafl's last eyewitness record is Linnaeus's 1732 tablut notes, containing a translation ambiguity (king escapes to *edge* vs. *corner*) that fueled a century of debate. Every historical pack therefore carries a research-status field, and generated games surface disputes ("historians disagree — this build uses X") rather than silently canonizing one school.

**Fact 9 — Structured prompting is the observed working pattern in the wild.** Successful one-shot game builds share a shape — experience spec + technical constraints + acceptance criteria + iteration loop — documented in an education-scale repo (prompt → `index.html`, with documented non-determinism) 【turn0search5】, a single-prompt game-building case study 【turn0search11】, Meta's one-shot game dev cookbook (structured prompt → single-file Three.js game), and community practice of dissecting these prompts 【turn0search10】. Reverse-engineered production system prompts (e.g., GitHub Spark) are publicly readable 【turn0search8】. The frontier critique holds that single-prompt-yields-single-artifact is too rigid, proposing *continual* generation instead (arXiv 2605.28258 【turn0search12】) — which the layered corpus directly supports.

**Fact 10 — Caching can become recursive.** Claude Artifacts may call the model via `window.claude.complete()` 【turn0search8】, so a *generated* game can issue its own cached-prefix requests against the same corpus at runtime. The static investment amortizes across the build step and every subsequent play-session call.

## 6. Operating Rules for Any LLM Working on This Project

You are an LLM operating inside this corpus. These are binding rules, each traceable to a Fact:

1. **Never improvise randomness.** All dice, draws, and shuffles resolve through the seeded universal RNG protocol in L1 — astragali, binary tetrahedral (Ur), casting sticks, cowries, and modern `XdY+Z` are all defined there. (Failure mode: the largest hallucination vector in race/RPG games.)
2. **Never invent game objects.** Tiles, pieces, and cells must pass inventory verification; begin every state-dependent answer with a canonical-notation restatement, per the cached output contract. (Fact 6.)
3. **Never solve; verify.** Emit instances and apply rules; delegate legality, uniqueness, and difficulty to the deterministic verifiers named in cached protocol blocks. (Fact 5.)
4. **Never canonize disputed history.** Ship competing reconstructions as alternate packs under one game, flag `attested/reconstructed/speculative`, and present disagreements to players verbatim. (Fact 8.)
5. **Order prompts static-first, variable-last.** This is not style; it is the prefix-exactness law. (Fact 2.)
6. **Add games as packs, not prompts.** A new game is a delta over an existing engine. If no engine fits, propose a new L1 engine explicitly before writing anything else. (Fact 7.)
7. **Patch the corpus, not the request.** Systematic failures update static blocks once; they never become per-request workarounds.
8. **Surface uncertainty.** If a rule, date, or parameter is uncertain, say so in the response; do not resolve silently.
9. **Respect attribution.** Cultural packs name their origin culture and sources; commercial reskins (Kalah, Ludo, Sudoku's Japanese branding) are documented as such. (Fact 8.)

## Part I — Prompt Caching: The Engineering Substrate

### 1.1 What Actually Gets Cached

An LLM does not read text; it computes **Key/Value (KV) tensors** — attention intermediates — for every token at every layer. On every autoregressive step the entire prefix must be prefilled. A 4K-token context can consume **~1.3 GB of GPU memory for KV alone** 【turn0search17】. Prompt caching stores those tensors server-side, keyed by an **exact prefix match**, so subsequent requests skip prefill entirely.

Measured results across providers: cost reductions of **50–90%** and latency reductions **up to 85% for long prompts** 【turn0search18】【turn0search15】, with dedicated evaluations confirming gains specifically on **long-horizon agentic workloads** — the exact profile of a game session or generation pipeline 【turn0search19】.

### 1.2 Provider Mechanics Comparison

| Property | Anthropic | OpenAI | Google Gemini | DeepSeek |
| :--- | :--- | :--- | :--- | :--- |
| Control | Explicit `cache_control` breakpoints (max 4) | Fully automatic prefix matching | Implicit + explicit `CachedContent` API | Automatic |
| Minimum cacheable | 1,024 tok (2,048 some models) | 1,024 tok | ~2,048 tok (model-dep.) | None (any prefix) |
| Write cost | 1.25× base input | None (free) | Free (implicit) | None |
| **Read cost** | **0.1× base** | **0.5× base** | **~0.25–0.75× (tiered)** | **0.1× base** |
| TTL | 5 min (refresh on hit); 1-hr option | ~5–10 min | Model-dependent | Hours |

Two consequences follow immediately:

1. **Anthropic/DeepSeek economics (0.1× reads) reward large static prefixes most** — a 10K-token cached prefix read 100 times costs the same as 1,000 fresh tokens. This is why the corpus architecture front-loads static content.
2. **OpenAI gives no manual control** — architecture must rely purely on byte-identical prefixes, making the "static-first ordering" rule non-negotiable across all providers.

### 1.3 The Prefix-Exactness Law

> ⚠️ **The single rule that shapes everything**: Caching is exact-prefix. A one-byte difference at position *N* invalidates the cache for everything after *N*. Therefore: **anything that varies between requests must appear as late in the prompt as possible.** Game name, theme, variant, and instance state come *last*; notation schemas, rule mechanics, output contracts come *first*.

This one law, mechanically derived, generates the entire layered architecture used throughout this report.

### 1.4 Recursion Opportunity: Artifacts Calling the API

Claude Artifacts run in a browser sandbox but now expose `window.claude.complete()` — allowing a generated game artifact to **compose and execute its own prompts against Claude** 【turn0search8】. A generated Mahjong tutor can thus issue cached-prefix requests itself. Cache farming becomes *recursive*: the static corpus amortizes across both the build step and every runtime call the built game ever makes.

## Part II — The Formal Theory of Games (Why the LLM Must Not Be the Solver)

### 2.1 Combinatorial Game Theory in One Paragraph

Conway's *On Numbers and Numbers* (1976) and Berlekamp/Conway/Guy's *Winning Ways* (1982) formalized every impartial/partizan game as a recursively defined position object with exact algebra — games literally *are numbers*. But the practical payload for this project is complexity theory: it tells us what to ask the LLM for and what never to ask.

### 2.2 State-Space Complexity and Solved Status

| Game | State-space size (Allis 1994 lineage) | Solved? |
| :--- | :--- | :--- |
| Tic-tac-toe | ~10³ | Draw (trivial) |
| Connect Four | ~10²¹ | Win for P1 (Allis, 1988) |
| Checkers | ~10²⁰ | **Draw (Schaeffer et al., 2007)** |
| Nine Men's Morris | ~10¹⁰ | Draw (Gasser, 1996) |
| Awari (Oware) | ~10¹² | **Draw (Romein, 2002)** |
| Backgammon | ~10²⁰ | Not solved |
| Chess | ~10⁴⁷ (tree ~10¹²⁰) | Not solved |
| Xiangqi | ~10⁴⁰ | Not solved |
| Shogi | ~10⁷¹ (drops → no stalemate) | Not solved |
| Go (19×19) | ~10¹⁷⁰ legal positions (Tromp, 2016) | Not solved |

### 2.3 Complexity Classes → Design Implication

Generalized chess is **EXPTIME-complete** (Fraenkel & Lichtenstein, 1981); generalized Go likewise (Robson, 1983); Hex and many placement games are **PSPACE-complete**. Translation: no efficient exact solver can exist for the generalized families.

> 💡 **The architectural consequence**: The LLM should **emit instances, apply rules, and narrate** — never "solve." Every solvability, legality, difficulty, and win-check claim must be delegated to a **deterministic verifier** called from the cached protocol block. This converts the LLM's failure modes (hallucinated rules, drifted state) into *caught errors* rather than silent corruption. It is the same lesson the multi-agent Game Master research reached empirically 【turn0search4】.

### 2.4 Notation Standards (the Compact-Encoding Layer)

| Domain | Standard | Density |
| :--- | :--- | :--- |
| Chess | FEN / PGN | Position in ~70 chars |
| Go | SGF + kifu coordinates | Whole game in hundreds of bytes |
| Mahjong | Tenhou/EMA notation (`123m456p789s1z`) | Hand in 10–15 tokens |
| Sudoku | 81-char row-major string | Whole puzzle in ~81 chars |
| Dice | `XdY+Z`, `kX`, exploding `!`, pools | Any RPG roll in a phrase |

Compact encodings are not cosmetic — they shrink the *dynamic* tail (which is always recomputed) and keep the cached prefix dominant in token share.

### 3.3 The Lost-Rules Problem and the Research-Status Protocol

Three canonical cases define the reconstruction pattern:

- **Senet** — boards abundant, rules absent. Kendall's and Piccione's competing reconstructions differ in movement direction and square meanings. **Corpus decision**: ship both as alternate rule packs under one game, flag `reconstructed: two-schools`.
- **Ur** — the Finkel tablet (a Babylonian scribe's rules, written ~2,400 years after the boards were made) gives bonus squares and dice values, but the exact route remains debated between "short route" and "long route" readings. **Corpus decision**: route as a parameter, dice engine locked to the binary tetrahedral protocol.
- **Tablut** — Linnaeus watched Sámi players in 1732, but a translation ambiguity in his notes (king escapes to *edge* vs. *corner*) spawned a century of debate. **Corpus decision**: escape condition as parameterized flag.

```markdown
# RESEARCH-STATUS FIELD (every historical game pack carries this)
status: attested | reconstructed | speculative
sources: [Finkel 2008; Kendall 1978; …]
disputed_parameters: [route_choice, escape_condition, piece_count]
presentation_rule: surface disputes to players as "historians disagree — 
  this build uses {X}" — never silently canonize one school
```

This field is the concrete mechanism for the *"deep iterative historical research"* mission: every session can append sources and upgrade statuses; the corpus is the research log.

# UNIVERSAL RNG PROTOCOL (Layer 1 — one write, serves every dice game ever)
## Modern: dN, XdY+Z, kX (keep), X! (exploding), adv/dis, pools ≥ T
## Historical modes (all parameterized, all seeded externally — the LLM
##   NEVER improvises a roll):

## Part IV — Cultural Families as Engine + Pack (the Taxonomy Core)

Murray's 1952 taxonomy and Parlett's work converge on the finding that world games cluster into a **small number of engine families** — which is exactly why "all games in all cultures" is a tractable prompt-corpus problem rather than thousands of unrelated prompts.

```mermaid
flowchart TD
    ROOT[World Games] --> RACE[Race engines<br>track + RNG]
    ROOT --> WAR[War/capture engines<br>pieces + capture]
    ROOT --> SOW[Sowing engine<br>count-and-capture]
    ROOT --> TILE[Tile engines<br>matching + hands]
    ROOT --> CARD[Card engines<br>deck + trick/shed]
    ROOT --> PUZZLE[Constraint engines<br>Latin-square grammar]
    ROOT --> RPG[Narrative engines<br>oracle + stats]
    RACE --> R1[Senet · Ur · Hounds & Jackals<br>Patolli · Pachisi · Ludo · S&L]
    WAR --> W1[Chess family · Tafl family<br>Alquerque → Checkers · Morris]
    SOW --> S1[Oware · Bao · Kalah · Congkak]
    TILE --> T1[Dominoes · Mahjong ·<br>solitaire branch · memory]
    CARD --> C1[Trick-taking · shedding · fishing<br>hanafuda yaku · rummy]
    PUZZLE --> P1[Nikoli galaxy · Sudoku ·<br>magic squares · Nonogram]
    RPG --> G1[Oracle engines · PbtA<br>d6/d10 pools · solo systems]
```

### 4.1 Race Family — One Engine, Seven Civilizations

Shared Layer-1 spec: linear/ring track, per-square effects table, movement from RNG block, bear-off/win condition, capture-on-landing flag. Every game above is a delta pack: Senet adds ritual squares 26–30; Ur adds rosette bonus squares and binary dice; Patolli is a cross-shaped 52-cell track with beans; Ludo is Pachisi commercialized (1896); Snakes & Ladders strips capture and adds virtue/vice topology (Gyan Chaupar's *moksha patam*). **Marginal cost per new civilization's game: one pack, ~200 tokens.**

### 4.2 Chess Family — Five Branches, One Piece-Hierarchy Engine

| Branch | Region | Signature deltas |
| :--- | :--- | :--- |
| Western chess | Europe | 1475 queen/bishop long-range reform |
| Xiangqi | China | River, palace, cannon-jump |
| Shogi | Japan | **Drops** (captured pieces redeploy) → 10⁷¹ states, few draws |
| Janggi | Korea | Palace-line moves; cannon must jump; no drops |
| Makruk / Sittuyin | Thailand / Myanmar | Weaker queen (seo); counted endgame |

### 4.3 Tafl and the Asymmetric-War Engine

Hnefatafl: attacker outnumbers defender ~2:1, defender's king escapes. The 1732 Linnaeus tablut record is the family's only eyewitness source — and its translation ambiguity (§3.3) is the perfect specimen for the research-status protocol. Asymmetric victory conditions are a reusable engine flag now seen in modern designs.

### 4.4 Mancala — The Largest Family on Earth

Sowing engine: rows of pits, seed distribution loop, capture rules, multi-lap rules. Oware (2×6+4, solved as a **draw by Romein, 2002**), Bao (Zanzibar; four rows; staged phases), Kalah (William Champion Jr., 1940s — a *commercial invention* that became the world's classroom mancala), Congkak/Sungka (maritime SE Asia). Hundreds of named regional variants = hundreds of packs over one engine — the highest pack-to-engine ratio in the corpus.

### 4.5 Tiles, Cards, and the Yaku-Pattern Engine

- **Dominoes** (Song China) and **mahjong** (1870s Ningbo) share the tile-inventory engine; the solitaire branch (Lockard's PLATO mahjong solitaire c. 1981 → *Shanghai* 1986; Shisen-Sho) adds layout assets — as mapped to the builder's tile-matching templates in the prior part.
- **Hanafuda** (12 flower suits × 4) runs the same **yaku-pattern matching machinery** as mahjong scoring — one shared scoring block, two games. Historical aside: Nintendo was founded in 1889 selling hanafuda.
- Card games: Parlett's taxonomy (trick-taking / shedding / fishing / matching / climbing / rummy) becomes six Layer-1 card engines; the Mamluk deck (c. 1400: cups, coins, swords, polo-sticks) is the ancestor asset pack.

### 4.6 The Number-Puzzle Lineage: Lo Shu → Euler → Garns → Nikoli

One continuous, citable chain: Lo Shu 3×3 magic square legend (c. 650 BCE) → Euler's Latin squares (1782) → 19th-century French newspaper squares (La France, 1895) → **Howard Garns's "Number Place," Dell, 1979** → Nikoli names it Sudoku (1984) and imposes givens-symmetry aesthetics → Wayne Gould's computer generator, *The Times*, Nov 2004 → global boom. Two hard research anchors: the **17-given minimum theorem** (McGuire et al., 2012 — 16 givens provably cannot force uniqueness) and the Nikoli invention wave (Slitherlink 1989, Hashiwokakero 1990, Nurikabe 1991) that turned one magazine into a genre factory. The whole lineage is one historical module serving every puzzle in the grammar from the prior part.

## Part V — Roleplaying and Dice: The Big-Payload Cache

### 5.1 Lineage

Kriegsspiel (Prussia, 1812 — umpires, fog of war) → H.G. Wells's *Little Wars* (1913) → David Arneson's *Braunstein* (1971, role-play inside a wargame) → *Chainmail* (1971) → **Dungeons & Dragons** (January 1974), which popularized the d4/d6/d8/d12/d20 toolkit and, eventually, the full dice-notation algebra. Dice pools arrive with Shadowrun (d6, 1989) and World of Darkness (d10, 1991); the 2d6 moves ladder with Apocalypse World (2010).

### 5.2 Why RPGs Are the Counterintuitive Cache Jackpot

The prior part's table bears repeating with evidence attached: static payload (rules 2–10K tokens, setting bibles up to 50K, bestiaries and oracle tables 3–20K) is enormous relative to dynamic state (~1–2K), so RPG sessions hit the highest *absolute* savings of any corpus category — and the known GM failure modes (state loss, under-challenging the player, acting for the player) documented in the Semantic Kernel digital-DM build 【turn0search2】 are exactly what the layered cache + Archivist-agent design corrects 【turn0search4】. Solo oracle engines (Mythic-style 2d6 likelihood ladders, action/theme d100 cross-tables, NPC trait triples) are pure lookup machinery — perfectly static, perfectly cacheable.

**Worked economics** (Anthropic-class pricing, illustrative): a Riichi tutor issuing 1M request-tokens/day at ~88% cached share → ~880K tokens billed at 0.1× ≈ **88K token-equivalents** vs 1M uncached — an order-of-magnitude saving before the latency dividend, consistent with the published 50–90% cost and up-to-85% latency figures 【turn0search18】【turn0search15】. The solo-RPG campaign (largest static payload, ~60K prefix) delivers the largest *absolute* per-request savings in the corpus.

**Governance** (condensed from the prior part): directory `L0…L5`; quality gates = verifier pass + cache hit-rate dashboard (targets L0 ≥99% … L3 ≥70%; cached-token share ≥85% in-genre); the failure→patch loop writes to *static blocks*, never to per-request retries.

## Closing Synthesis

Five findings define the whole terrain. **First**, cache economics are prefix-exact and therefore *architectural* — the layered L0–L4 stack is not a style choice but a mechanical consequence of how KV reuse is priced (0.1× reads, 85% latency cuts) 【turn0search18】. **Second**, complexity theory forbids the LLM from being the solver, which is a gift: it tells us every fragile claim belongs in a deterministic verifier, and the corpus's biggest hallucination risks (tiles, dice, uniqueness) all have cheap cached fixes. **Third**, five millennia of world games compress into ~six engine families — Murray's taxonomy turned out to be a cache manifest — so "all games in all cultures" costs thousands of ~200-token packs, not thousands of prompts, with disputed history handled honestly via research-status flags. **Fourth**, the retrieved corpus shows the field's working pattern is already structural (experience + constraints + acceptance criteria + iteration 【turn0search5】【turn0search13】), with the frontier moving from one-shot artifacts to continual, self-calling systems 【turn0search12】【turn0search8】 — exactly where a recursive cache corpus compounds hardest. **Fifth**, the RPG category, assumed uncacheable, is the largest absolute prize because its static payload is the biggest.

The build order stands: Layer 0 + race/dice engine first (it lights up Senet through Ludo in one write), the Nikoli grammar second (Sudoku becomes ten games), the solo-RPG stack third (the biggest savings). Everything after that is archaeology — and the corpus is the dig site.
