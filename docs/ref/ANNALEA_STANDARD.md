# ANNALEA STANDARD for Wave Receipts

This document defines the "Annalea Standard" for `wave_receipts` within the `local_sovereign_agent` fleet. This standard ensures consistent and verifiable recording of lane-level failure logs, token counts, and cryptographic hashes for every wave execution.

## 1. Scope
This standard applies to all `wave_receipts` generated by the `local_sovereign_agent` fleet, specifically those pertaining to individual execution lanes within a wave.

## 2. Receipt Structure
Each `wave_receipt` MUST be a JSON object with the following top-level keys:

- `wave_id`: (string) A unique identifier for the parent wave.
- `lane_id`: (string) A unique identifier for the individual lane within the wave.
- `timestamp_utc`: (string) ISO 8601 formatted timestamp of the receipt generation in UTC.
- `status`: (string) The final execution status of the lane (e.g., "SUCCESS", "FAILURE", "TIMEOUT", "INTERRUPTED").
- `execution_details`: (object) Contains details about the lane's execution.
    - `model_name`: (string) The name of the LLM model used for this lane.
    - `prompt_tokens`: (integer) The number of tokens in the prompt.
    - `completion_tokens`: (integer) The number of tokens in the completion.
    - `total_tokens`: (integer) The sum of `prompt_tokens` and `completion_tokens`.
    - `duration_ms`: (integer) The execution duration of the lane in milliseconds.
    - `cost_usd`: (float) The estimated cost of the lane's execution in USD.
- `logs`: (array of strings) A chronological list of significant log messages or events during the lane's execution. This should include error messages if `status` is "FAILURE".
- `input_hash`: (string) SHA256 hash of the sanitized input provided to the lane.
- `output_hash`: (string) SHA256 hash of the sanitized output generated by the lane.
- `proof_of_work`: (string, optional) Cryptographic proof of computational work, if applicable.

## 3. Failure Logging
In case of a `status` of "FAILURE", the `logs` array MUST contain detailed error messages, stack traces, and any relevant context to diagnose the failure. Sensitive information SHOULD be redacted prior to logging.

## 4. Hash Calculation
All hashes (`input_hash`, `output_hash`) MUST be calculated using SHA256. The input and output content MUST be canonized (e.g., whitespace trimmed, JSON minified) before hashing to ensure consistent hashes across different environments.

## 5. Audit Trail
Each `wave_receipt` will be appended to the Verkle chain, providing an immutable audit trail of wave execution. The `wave_id` and `lane_id` will serve as key identifiers for querying specific lane histories.
